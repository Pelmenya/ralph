# `examples/` — шаблоны для человека со стороны

Здесь лежит то, что пользователь копирует в СВОЙ репозиторий, а не то, что исполняет ядро.
Это шаблон демо `demo/`, путь входа по [инструкции демо](../docs/demo.md), и шаблон данных
хуков `hooks.json.example`. Общие правила репозитория — в [корне канона](../CLAUDE.md).

| Путь                               | Что это                                                      |
| ---------------------------------- | ------------------------------------------------------------ |
| `demo/src/`, `demo/test/`          | библиотека строк на одной функции и её тесты на `node:test`  |
| `demo/cards/`                      | тексты двух карточек одной вехи: шапка YAML и тело           |
| `demo/.claude/ralph/`              | конфиг раннера и проектная половина правил сессии демо       |
| `demo/.claude/settings.json`       | проводка барьера сессий; сами хуки копируются из установки   |
| `demo/package.json`, `demo/README` | гейт демо и описание проекта для его будущего репозитория    |
| `hooks.json.example`               | данные хуков потребителя: MCP-мутации форжа, таблица скиллов |

## Местные правила

**Шаблон самодостаточен.** Его копируют целиком в пустой репозиторий, где нет ни канона,
ни `node_modules`: импорт из `core/`, путь наружу `demo/` или зависимость в
`package.json` сломают демо у человека, который ещё не знает, где искать причину.
Поэтому гейт демо — две детерминированные команды без зависимостей и без сети.

**Расхождение с ядром краснеет здесь, а не на dry-run пользователя.** Конфиг, который ядро
отвергнет, карточка мимо вехи или роутинга, чек гейта без скрипта в `package.json`,
проводка барьера, которую не пропустит проба на старте, — всё это ловит
`tests/demo-dry-run.test.ts` настоящими `resolveProfile`, preflight и dry-проходом петли.
Он же исполняет тесты шаблона: vitest канона `*.test.mjs` не подхватывает, а процесс
`node --test` тест запустить не вправе, поэтому файл тестов импортируется с подменённым
`node:test`. Правишь шаблон или контракт конфига — гони этот набор.

**Плейсхолдеры — абстрактные.** Логин в `authorAllowlist` — `your-login`, организация —
`your-org`: шаблон лежит в публичном дереве, и скан следов проверяет его наравне с кодом.
