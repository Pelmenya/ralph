# Ralph

Автономный раннер разработки: берёт задачу из трекера, запускает кодер-сессию, гоняет
гейт, проводит ревью и доводит фазу до мерджа — без человека в цикле, но с барьерами,
которые останавливают петлю там, где решение обязан принять человек.

**Состояние: ранний.** Ядро вынесено в этот репозиторий из двух проектов, где оно жило
копиями и успело разойтись; здесь — сведённое дерево. Свой гейт есть и зелёный на чистом
клоне; контракт подключения ещё делается. Пока это не продукт «поставил и работает», а
ядро, которое подключают, зная, что делают.

## Что это, если по существу

Петля устроена вокруг двух идей.

**Барьеры важнее промптов.** Всё, что должно соблюдаться, проверяется кодом, а не
просьбой к модели: предохранитель побочек в тестах, fail-closed на битом конфиге, предел
намерений одной сессии, детач-парковка рабочего дерева, deadman по свежести лога. Модель
может ошибиться или «убедить себя» — барьер не может.

**Остановка дороже ошибки, но дешевле молчания.** Красный гейт, тупик разбора, недоступный
рантайм — разные события, и раннер их различает: транзиент переживает повтором, отказ по
существу останавливает петлю и называет причину, а не глохнет.

## Раскладка

| Каталог      | Что внутри                                                                       |
| ------------ | -------------------------------------------------------------------------------- |
| `core/`      | петля: оркестратор, гейт, ревью, состояние и лок, worktree, конфиг-профили       |
| `adapters/`  | швы: источник задач, форж, рантайм кодера, нотификатор, проверка деплоя          |
| `runtime/`   | монитор-дашборд, deadman, уведомления                                            |
| `shared/`    | утилиты и предохранитель побочек                                                 |
| `tests/`     | сценарные прогоны, барьеры чистоты, фикстура чужого проекта                      |
| `provision/` | продуктовая часть провижна: юнит systemd (шаблон), запуск в tmux, ротация токена |

Ядро — TypeScript без билд-шага: исполняется нативным type stripping Node 24. В каждой
папке лежит `AGENTS.md` с её правилами; общие — в [AGENTS.md](AGENTS.md) корня.

## Разработка

```
npm ci
npm run gate   # формат → типы → сьют, fail-fast
```

Гейт зелёный на чистом клоне: ничего, кроме `npm ci`, для него не нужно. Отдельные шаги —
`npm test`, `npm run typecheck`, `npm run format:check`.

## Как это подключается

Проект-потребитель держит ядро подмодулем и свой `ralph.config.json` рядом: фазы, состав
чеков гейта, метки роутинга моделей, профили. Ядро знает **контракт**, а не команды
конкретного проекта — состав гейта, имена меток и milestone'ов приходят из конфига.

Скрипты, которые ядро зовёт у потребителя (синк доски, журнал находок ревью), задаются
там же — секцией `consumerScripts`. Путь не задан либо равен `null` — вызов выключен, и об
этом сказано в логе; в каноне таких файлов нет, и ядро больше не требует их по зашитому
имени. Относительный путь якорится к корню потребителя, если раскладка корней задана
секцией `roots`; без неё он, как и раньше, считается от каталога, в котором раннер работает.

**Дерево потребителя после мерджа фазы подтягивает сам раннер** — `fetch` плюс
`merge --ff-only`, сразу после сдачи фазы. Иначе скрипты, заякоренные к корню потребителя,
оставались бы той версии, которую человек в последний раз забрал руками. Обновление
best-effort и осторожное: грязное дерево, чужая ветка, detached HEAD и любое расхождение с
`origin/main` — повод не трогать и сказать об этом в логе вместе с командой, которой человек
закончит сам. В подмодули оно не рекурсирует — и запрет стоит явно, потому что дефолт `git`
здесь обратный: ревизию продукта меняет lifecycle-операция, а не обновление соседнего дерева.

Контракт подключения (раскладка каталогов, launcher, миграция состояния) сейчас
дорабатывается; до его закрытия подключение ручное.

## Чего здесь нет намеренно

Ни одного имени проекта-потребителя, ни одного пути конкретной машины — репозиторий
публичный, и утечка сюда необратима. Это не дисциплина, а чек: `tests/project-traces.ts`
сканирует дерево **и сообщения коммитов** по структурным классам, а словарь имён приходит
снаружи (`RALPH_TRACE_DENY`), потому что список «этих имён тут быть не должно» сам был бы
следом.
