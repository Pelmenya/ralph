# Фикстуры ответов площадки

Ответы SourceCraft, снятые живьём 06.09.2026 и **обрезанные**, а не выдуманные: разбор
чужого API проверяется по тому, что сервер отдаёт на самом деле, — спека расходится
с ним систематически.

| Файл                                       | Что это                                                                  |
| ------------------------------------------ | ------------------------------------------------------------------------ |
| `sourcecraft-merge-checks-success.json`    | `GET …/pulls/125/merge-checks` дословно                                  |
| `sourcecraft-merge-checks-processing.json` | тот же ответ со статусом `processing`/`in_progress`                      |
| `sourcecraft-merge-checks-failed.json`     | тот же ответ со статусом `failed`/`failure`                              |
| `sourcecraft-run-356-failed.json`          | `GET …/cicd/runs/356` — прогон с красным кубом `test`, кубы прорежены    |
| `sourcecraft-cube-log-350-oom.txt`         | хвост лога куба `test` прогона 350: OOM контейнера гейта, ANSI сохранён  |
| `sourcecraft-cube-log-356-failed-test.txt` | хвост лога куба `test` прогона 356: настоящий отказ теста, ANSI сохранён |

**Два файла merge-checks собраны из третьего заменой статусов.** Живого красного ответа
взять неоткуда: `merge-checks` отдаёт ПОСЛЕДНИЙ прогон каждого workflow, и после мерджа
он уже зелёный. Значения статусов при этом не выдуманы — они из энума `Run.Status`
OpenAPI-спеки площадки (`created`, `prepared`, `processing`, `success`, `failed`,
`canceled`, `timeout`, `skipped`, `awaiting_approval`, `rejected`); общий `status`
у `MergeChecks.Status` свой и короче — `in_progress`, `success`, `failure`.

**Живой КРАСНЫЙ ответ `merge-checks` снять пока неоткуда — снимите его при первом же
настоящем красном прогоне** и замените им оба собранных файла. Это ровно тот случай, про
который предупреждает `docs/platform/sourcecraft/api-gotchas.md` («спека врёт — прав
сервер»): значения статусов взяты из энума, но КАК сервер заполняет остальные поля
красного ответа, здесь пока предположение.

**ANSI в логах намеренно сохранён.** Куб отдаёт лог одной строкой с escape-последова­
тельностями, и очистка — часть разбора: без неё сессия лечения получает нечитаемый текст,
а поиск сигнатур отказа спотыкается о вставки посреди слов.

## Исход сессии рантайма

| Файл                           | Что это                                                                |
| ------------------------------ | ---------------------------------------------------------------------- |
| `session-end-claude.json`      | вывод Claude Code CLI 2.1.311 на семь исходов (и Kimi — тот же бинарь) |
| `session-end-codex.json`       | вывод codex-cli 0.163.0 на шесть исходов; бюджета ходов у него нет     |
| `session-end-kimi-native.json` | вывод Kimi Code 2.3.2 (`kimi -p`, stream-json) на семь исходов         |
| `session-end-opencode.json`    | вывод OpenCode 1.19.4 (`run --format json`); бюджета ходов у него нет  |

У каждого случая поле `source` говорит, откуда он, и это не формальность: живьём снят не
каждый. Дословно живые — успех и исчерпание ходов Claude (JSON-результат, токены вырезаны) и
тексты лимита, ответа 524 и оборванного соединения из транскриптов CLI. Формулировки входа,
перегрузки сервера и все сообщения Codex взяты из строк самих бинарей указанных версий:
вызвать лимит или отзыв токена ради фикстуры значило бы сжечь квоту или вход. Конверт
JSON-результата Claude вокруг таких текстов собран по форме живого ответа. **Снимите живой
ответ при первом настоящем отказе** — лимите, отзыве входа, обрыве — и замените собранный.

**Обрыв прокси с кодом 0 лежит в двух формах.** Инцидент 16.10 снят в текстовом режиме, а
боевой spawn всегда идёт с `--output-format json`, и там CLI кладёт ответ прокси в `result`
конверта успеха — `is_error: false`. Без случая в JSON-форме сьют оставался зелёным, когда
классификатор переставал узнавать обрыв на боевом пути. Конверт этого случая собран: при
следующем отказе прокси снимите живой JSON-ответ.

**Для Kimi формулировки провайдера не сняты.** Бинарь у Kimi тот же, и форма отказа CLI —
`API Error: <код> <тело>` — та же, но тело ответа приходит от Moonshot, а не от Anthropic.
Поэтому лимит Kimi узнаётся по коду `429`, а не по словам тела, и единственный случай с телом
Moonshot в `session-end-claude.json` собран по форме его ошибок. Contract suite для `kimi`
зелёный на фикстурах Claude: он проверяет боевой spawn-путь Kimi, но не тексты Moonshot.
Снимите живой отказ Kimi при первом же лимите или отзыве ключа и положите его отдельным
случаем.

**Kimi Code (`kimi-native`) снят живьём там, где это не стоило квоты или входа**: успех,
бюджет шагов (`KIMI_LOOP_MAX_STEPS_PER_TURN=1`), два отказа входа (пустой дом и дом без
ключей), срок раннера (CLI ловит SIGTERM и выходит 143 без сигнала) и пустой промпт. Лимит,
квота, отзыв ключа, обрыв и перегрузка — коды из закрытого списка ошибок бинаря 2.3.2 в форме
его строки отказа, тела ответов провайдера собраны. Время сброса окна CLI в строку не кладёт.
Снимите живой отказ при первом настоящем лимите или обрыве и замените собранный.

**OpenCode снят живьём почти целиком** (27.10, #121): успех, отрицательная проба барьера
(сессия с тремя отменёнными плагином вызовами — исход по-прежнему `completed`), 503 провайдера,
401 на недействительном ключе, неизвестная модель (`UnknownError` без причины) и срок раннера
(сигнал SIGTERM — CLI его сам не ловит). Заголовки ответа обрезаны, хост провайдера заменён.
Собран один случай — 429: форма события `error` та же, что у живых 503 и 401, код и
`retry-after` вписаны. Снимите живой лимит при первом настоящем и замените собранный.

**Время сброса окна разбирается вместе с зоной.** У Claude это суффикс «resets 8:20pm
(UTC)», и без него время считается локальным; у Codex — «try again at Oct 27th, 2026 3:05
PM» без зоны, локальным временем процесса CLI на том же хосте. Незнакомая зона и прошедший
момент — ожидание по `apiLimitFallbackWaitMin`, а не догадка.

## Вход хука у каждого харнесса

| Файл               | Что это                                                                        |
| ------------------ | ------------------------------------------------------------------------------ |
| `hook-events.json` | PreToolUse-событие Claude Code, Codex и Kimi Code со стенда Фазы 11 и OpenCode |

Claude Code, Codex и Kimi Code сняты живьём: это вход внешнего хука стенда
(`provision/install-stand.sh`, проба `block`) из его журнала. Журнал стенда пишет первые 400
знаков, поэтому у Claude Code и Codex хвост после `tool_input.command` не снят; пути машины
заменены абстрактными. Все три CLI подают одну форму — Claude Code: `tool_name: "Bash"`,
`tool_input.command`. Различие — в соседних полях (`turn_id` у Codex, `client_type` и
`tool_call_id` у Kimi) и в аргументах файловых инструментов Kimi (`path`, а не `file_path`).

**Событие OpenCode снято живьём прогоном адаптера** (#121): второй плагин рядом с плагином
барьера записал аргументы `tool.execute.before` — `{tool, sessionID, callID}` и `{args}`. Два
вызова: `bash` (`command`) и `read` (`filePath`, а не `file_path`); заменён только путь файла.
