# Демо: ралф на маленьком проекте за полчаса

Демо показывает главное — карточка проходит путь от трекера до мерджа без человека:
раннер берёт задачу, кодер-сессия пишет код и тест, гейт гоняет проверки, ревью-сессия
читает дифф, раннер мерджит PR и закрывает карточки.

Шаблон проекта лежит в каноне, в `examples/demo/`: библиотека строк на одной функции,
гейт из двух детерминированных команд (`npm run syntax`, `npm test`, зависимостей нет) и
две карточки в одной вехе (`cards/`). Ниже — ручная установка ядра; launcher, который
делает это одной командой, появится позже.

Пути ниже — форма, а не адреса: `<канон>` — клон этого репозитория, `<установка>` —
каталог, куда ставится ядро, `<демо>` — клон вашего демо-репозитория.

## Что нужно заранее

- Node 24 и git ≥ 2.29.
- Claude Code (`claude`) с выполненным входом: на старте раннер проверяет, что кодер-рантайм
  запускается, и без него не стартует.
- Аккаунт SourceCraft и токен с правом читать и менять карточки, ветки и PR.

## 1. Поставить ядро

Ядро исполняется из отдельного клона на зафиксированной ревизии, а не из дерева, которое
петля правит:

```bash
git clone <адрес-канона> <канон>
rev=$(git -C <канон> rev-parse --short HEAD)
git clone --no-checkout <канон> <установка>/$rev
git -C <установка>/$rev checkout --detach $rev
```

Рантайм-зависимостей у ядра нет: `npm ci` в установке не нужен.

## 2. Завести демо-репозиторий

1. Создайте на SourceCraft **публичный** пустой репозиторий, например `your-org/ralph-demo`,
   и склонируйте его в `<демо>`.
2. Скопируйте шаблон и то, что раннер требует от дерева сессий, из установки ядра:

    ```bash
    cp -r <установка>/$rev/examples/demo/. <демо>/
    cp <установка>/$rev/ralph.md <демо>/
    mkdir -p <демо>/.claude/hooks
    cp <установка>/$rev/.claude/hooks/*.cjs <демо>/.claude/hooks/
    ```

    `ralph.md` — переносимая половина правил сессии: на него ссылается промпт конфига.
    Каталог `.claude/hooks/` — барьер сессий (`guard.cjs`): сессии идут под
    `bypassPermissions`, где держит только он, и раннер перед первой сессией проверяет его
    пробой — без хуков петля не стартует. Данных хуков (`.claude/ralph/hooks.json`, шаблон —
    `examples/hooks.json.example`) демо не нужно: сессии петли в трекер не ходят, а без
    файла контур самый строгий — ни одной MCP-мутации.

3. В `<демо>/.claude/ralph/ralph.config.json` замените `your-login` в `authorAllowlist` на
   свой логин SourceCraft. Карточки чужих авторов раннер не берёт: в публичном репозитории
   текст карточки — это инструкция сессии, работающей без подтверждений.
4. Закоммитьте и запушьте в `main`:

    ```bash
    cd <демо>
    git add -A && git commit -m "chore: демо-проект для ралфа" && git push origin main
    ```

## 3. Завести веху и две карточки

В трекере демо-репозитория:

1. Веха с именем ровно как в `phases[0].milestone` конфига: `Демо · Фаза 1: Строки`.
2. Две карточки из `cards/01-truncate.md` и `cards/02-word-count.md`: заголовок — `title`
   из шапки файла, тело — всё, что ниже шапки, метки — `labels`, веха — созданная выше.
   Метки `complexity:low` и `area:lib` создайте, если их ещё нет. Автор карточек — тот
   логин, что вписан в `authorAllowlist`.

## 4. Окружение

Секреты — только в окружении, не в дереве и не в конфиге:

| Переменная               | Значение                                  |
| ------------------------ | ----------------------------------------- |
| `SOURCECRAFT_TOKEN`      | токен SourceCraft                         |
| `RALPH_SOURCECRAFT_ORG`  | организация демо-репозитория (`your-org`) |
| `RALPH_SOURCECRAFT_REPO` | имя демо-репозитория (`ralph-demo`)       |

Telegram для демо не нужен: профиль `demo` не шлёт пуш-событий.

## 5. Dry-run

```bash
cd <демо>
node <установка>/$rev/ralph.js --dry-run
```

Dry-run read-only: лок не берёт, state не пишет, в трекер не пишет. Вывод — в терминале;
файлом он ложится в `ralph.dry.log` дерева раннера (см. шаг 6), и только если это дерево
уже создано: первый dry-run пишет только в терминал. Зелёный — это строка
`Проба барьера пройдена` и план первой итерации: веха демо и одна из двух карточек, без
отказов конфига.

| Что видно                                               | Что сделать                                                      |
| ------------------------------------------------------- | ---------------------------------------------------------------- |
| `Не найден/не парсится .claude/ralph/ralph.config.json` | запуск не из корня `<демо>`                                      |
| отказ про `permissionMode`                              | опечатка в режиме — значение уходит в CLI как есть, поэтому стоп |
| отказ про кодер-рантайм                                 | `claude` не установлен или не в `PATH`                           |
| отказ пробы барьера                                     | не скопированы `.claude/hooks/*.cjs`                             |
| `SourceCraft: не заданы org/repo`                       | не заданы переменные окружения из шага 4                         |
| очередь пуста                                           | карточки не в той вехе либо автор не из `authorAllowlist`        |

## 6. Боевой прогон

```bash
node <установка>/$rev/ralph.js
```

Раннер создаст ветку `feature/demo-phase-1-strings`, по сессии на карточку, закроет обе,
откроет PR, проведёт ревью, прогонит гейт и смерджит.

Работает раннер не в `<демо>`, а в своём worktree рядом с ним: `<демо>/../ralph-demo-ralph`
(имя задаёт `runnerWorktreeDirname` конфига). Каталог он создаёт сам на первом боевом
запуске, и состояние прогона лежит там, а не в `<демо>`:

- ход — в `<демо>/../ralph-demo-ralph/.claude/ralph/ralph.dry.log`. Имя не опечатка:
  `ralph.log` пишет только профиль `prod`, у демо профиль `demo`;
- мягкая остановка — файл `<демо>/../ralph-demo-ralph/.claude/ralph/ralph.stop`: петля
  встанет на границе шага. Тот же файл, положенный в `<демо>/.claude/ralph/`, петлю не
  остановит.
