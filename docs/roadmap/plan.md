# Plan: Ralph после хакатона — надёжная петля и отдельный продукт

**PRD:** `docs/roadmap/prd.md` · обзор — `roadmap.md` · второе мнение по доставке — `delivery-second-opinions.md`
**Дата:** 2026-10-26 (редакция 2 — после ревью Codex gpt-6-astra и Kimi K3.1 Pro;
редакция 3 того же дня — Фаза 16b: четыре харнесса под одним контрактом;

**Трекер:** `pelmenya/ralph`

## Что изменилось во второй редакции

Ревью двух моделей (полные тексты — вне репозитория, в рабочем каталоге оператора) и решения
человека 26.10:

- **guard раньше автономии.** Петля на каноне стартует только после минимального guard
  с отрицательной пробой. Сейчас канон регистрирует только `SessionStart` и `PostToolUse`,
  без `PreToolUse`. Раньше guard стоял в Фазе 9, теперь — в S0 (Фаза 2).
- **Синхронизация по manifest.** В `.claude/ralph` потребителя лежат его `ralph.config.json`
  и `ralph.project.md`, поэтому сверка всего каталога затёрла бы конфиг живой петли.
- **У каждой миграции свой откат.** Прежняя копия удаляется только после доказанного
  возврата на неё. Сначала GitHub-полигон, потом SourceCraft-прод.
- **Вернулся запрет второго writer** на тот же `repo_id` (PRD «Не в скоупе», R15).
- **R6 полностью:** для `required` CI блокирует и неизвестная свежесть прогона.
- **R2 в каноне уже атомарен** (`writeFileAtomic`): в задаче остались схема, версия
  и различение «повреждён / отсутствует».
- **Крупные карточки разбиты по путям исполнения:** матрица окон падения, журнал этапов,
  launcher.
- **Стенд внешней установки (бывшая Фаза 9) — только эксперименты CLI.** Обрывы
  update/rollback проверяются на готовом launcher.
- **Протокол update:** подготовка ревизии идёт без остановки петли, активация — рестартом
  на подтверждённой границе.
- **Решения человека 26.10:**
    1. S0 — на этой неделе руками;
    2. метрика продукта — в S1;
    3. демо и путь входа — сразу после S1;
    4. «лучшее берём у всех» — у каждого взятого механизма указан источник.

## Кто исполняет и когда

- **Фазы 0–2 (S0) — человек и вахта, на этой неделе (26.10–01.11).** Уборка трекера —
  решение человека, сведение — суждение по каждому расхождению. Петля пока работает
  на копии SourceCraft-монорепо.
- **С Фазы 3 — петля на каноне** как на обычном потребителе отдельного репозитория.
  Очередь петли переключается между репозиториями, двух петель одновременно нет — это
  сторожит preflight из Фазы 2.
- **Решения человека 26.10 для петли на каноне** (записаны в задаче 77): с Фазы 3 —
  без ship человека; роутинг моделей кодера по сложности выключен до чисел Фазы 4; ревью
  всегда на сильнейшей модели. Кодер и ревьюер — Claude Code, пока Фаза 17 не даст
  маршрут ролей; Kimi до тех пор — второе мнение по копии дерева.
- **Цель по харнессам — универсальность:** Claude Code, Codex, Kimi Code и OpenCode
  под одним контрактом рантайма (`docs/harness-adapters.md`), и пятый подключается
  пакетом адаптера без правки ядра (`docs/harness-contract.md`). Запуск и регистрация guard
  каждого харнесса — Фаза 16b; барьеры по нормализованному событию и запертый конфиг
  харнесса — каркас 16c и пакеты 16d; песочница и доказательства скиллов — 16e; правила, соответствие и эталонный пятый харнесс — 16f; допуск профилей в роли — 17.
