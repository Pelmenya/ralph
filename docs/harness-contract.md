# Харнесс как пакет адаптера: контракт, по которому подключается любой агентный CLI

**Дата**: 2026-10-27
**Статус**: Draft, основание для Фаз 16c–16e (`roadmap/plan.md`). Вторые мнения — Kimi K3.1 Pro
(16 находок) и Codex gpt-6-astra (18 находок), обе учтены.

**Что уже есть и чего ещё нет.** Фаза 16b проводит в запуск все четыре харнесса: Codex —
регистрацией в argv, Kimi Code — домом CLI, который раннер собирает перед сессией, OpenCode —
плагином (статус «экспериментальный»). Живая отрицательная проба у Kimi Code и OpenCode
пройдена на `Bash` и чтении `.env`. Общие барьеры при этом принимают вход в форме Claude Code,
а конфиг Kimi Code и OpenCode сливается с конфигом человека. Всё, что ниже названо событием,
пакетом и набором соответствия, — цель Фаз 16c–16e, а не описание текущего кода.

Канон вырос на Claude Code, и его барьеры говорят на языке Claude Code: имена
инструментов `Edit`/`Write`/`Bash`, поле `file_path`, транскрипт JSONL с вызовом `Skill`,
`settings.json`, `mcp__<server>__<tool>`. Разбор 27.10 (бинари codex-cli 0.163.0, Kimi
Code 2.3.2, OpenCode 1.19.4, их документация и история сессий стенда Фазы 11) показал, что
у трёх харнессов в разных сочетаниях барьеры молча пропускают одни запреты и навсегда
блокируют другие.

Цель — чтобы подключение харнесса не было переносом допущений Claude по одному. Харнесс
подключается **пакетом адаптера** вне `core/` и общих барьеров: описание (данные),
нормализатор события, регистратор барьера, сборщик конфига и чтение истории (код).
Произвольный CLI одними данными не подключить, и документ этого не обещает. Обещание
другое: для нового CLI не правятся ядро и общие барьеры.

## Что нашёл разбор

Серьёзность: **дыра** — запрет проходит молча; **ложный блок** — разрешённое блокируется
без выхода; **дрейф** — поведение меняется без нашего ведома. Пометка «по доке» — живой
фикстуры события ещё нет.

Три общих корня. **Барьер, не узнавший событие, разрешает его** (`guard-rules.cjs`, ветка
«незнакомый инструмент» → `ALLOWED`): одно это правило дало половину дыр таблицы.
**Харнесс исполняет конфиг из дерева, которое правит агент**, причём уже при старте —
защита путей от записи не помогает, слой мог лежать в дереве до сессии. **Механизм
перехвата сам может отказать**, и у трёх CLI из четырёх отказ означает пропуск.

MCP-allowlist по имени у Kimi Code работает, как у Claude, но не покрывает подмену сервера
через конфиг. Codex и OpenCode на стенде проверялись только на `Bash`: их файловые пути и
MCP отрицательной пробой не покрыты.

## Принципы

1. **Незнакомое — запрет.** Инструмент не из описания, поле, которое не разобралось,
   MCP-имя без отображения в описании, невалидная операция — блок с причиной. Если
   невалидна или запрещена хотя бы одна операция вызова, запрещён весь вызов; все операции
   судятся до первого эффекта. Возможность, которую барьер не умеет судить (`fetch` без
   политики сети, `agent` без наследования барьеров), запрещена, пока не умеет.
2. **Общие барьеры не знают харнессов.** `guard-rules.cjs`, `skill-barrier.cjs` и проверка
   данных контура принимают нормализованное событие и доверенный контекст сессии. Сырой
   вход CLI до них не доходит. Независимость проверяется зависимостями модулей и
   отсутствием ветвления по идентичности харнесса; поиск имён — вспомогательная проверка.
3. **Хук — барьер качества, граница доверия — песочница.** Хук не видит путь, собранный
   скриптом по частям, и не держит отказ собственного механизма у CLI, которые такой отказ
   пропускают. Поэтому гарантия «агент не меняет конфиг, пакет, политику и доказательства»
   держится песочницей, где эти пути процессу сессии недоступны на запись, у каждого
   харнесса. Без песочницы гарантии хуков названы ограниченными, а не полными.
4. **Исполняемый конфиг дерева не исполняется.** Конфиг харнесса собирает раннер в каталоге
   состояния. Проектные исполняемые слои (хуки, плагины, инструменты, MCP-серверы)
   выключаются; где нельзя — preflight отвергает их наличие в дереве и в его предках. CLI,
   у которого нельзя ни того, ни другого, набор соответствия не проходит.
5. **Регистрацию подтверждает CLI, а не наш разбор.** Проба идёт той же командой, с тем же
   окружением и домом, что сессия. Предупреждение CLI об отброшенной секции — отказ старта.
   Обработанная ошибка правила — блок двойкой; отказ механизма перехвата — блок там, где
   механизм наш (плагин OpenCode), и объявленное ограничение там, где нет.
6. **Доказательство — доверенное и полное.** Загрузка скилла доказывается доверенным
   источником пакета: успешное событие той же сессии, имя и хеш скилла, полная доставка,
   порядок до правки. Кэш или файл, который сессия может записать сама, доказательством не
   является. Где активации нет (Codex читает `SKILL.md` оболочкой), критерий называется
   честно — «эквивалентная доставка инструкций».
7. **Правила доставляет раннер.** Контракт сессии приходит в промпт или флагом инструкций
   харнесса, а не фразой «прочитай файл». Какие файлы правил харнесс читает сам и с каким
   бюджетом — объявление описания; доставка проверяется вместе с остальными инструкциями.
8. **Опасные пробы — только на стенде, и проба доказывает правило.** Живая отрицательная
   проба идёт в изолированном стенде с фиктивным MCP и безопасными целями. Зелёная проба —
   это факт попытки вызова, событие у барьера, ожидаемая причина и отсутствие эффекта, в
   паре с разрешённой пробой в тех же условиях, у которой эффект есть. Любой код 2 любого
   хука пробу не засчитывает.

## Пакет адаптера

Каталог `adapters/harnesses/<имя>/` с версионированным интерфейсом. Раннер находит пакет
через реестр, ядро выбирает его по конфигу, хуки получают его нормализатор и контекст от
раннера. Выбор харнесса по `switch` в ядре и список `GUARD_WIRED_HARNESSES` уходят за реестр.

| Часть           | Что даёт                                                                                                                                                                        | Кто сверяет                                                  |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| описание        | версия CLI; `toolMap` (имя → операция); `argMap` (пути, шаблоны, база, назначение); `eventCoverage` (каналы исполнения: прямые, вложенные, продолжения процессов — перехват или | генератор матрицы проб; сверка с инвентарём самого CLI       |
|                 | доказанное отключение); `configSurfaces`; запрещённые переменные; MCP-отображение `emittedName → {server, tool}`, снятое живьём; источник доказательства скилла; правила        |                                                              |
| нормализатор    | сырой вход CLI → `ToolEvent`; незнакомое → `unknown`                                                                                                                            | фикстуры, снятые живьём                                      |
| регистратор     | регистрация барьера в формате CLI, обратное чтение того, что уйдёт в CLI; признак принятия регистрации самим CLI                                                                | проба на собранной команде                                   |
| сборщик конфига | дом CLI в каталоге состояния, серверы MCP раннера, выключенные проектные слои, вычищенное окружение                                                                             | preflight; конфиг человека не трогается                      |
| чтение истории  | поставщик доказательств контекста сессии                                                                                                                                        | пробы: подделка в той же сессии, чужая сессия, битая история |
| исход           | классификатор `SessionEndReason`, `turnLimit`, стоимость попытки                                                                                                                | contract suite Фазы 16                                       |

Вход общих барьеров — дискриминированное объединение с обязательными полями и исполняемой
валидацией:

```ts
type ToolOperation =
    | { op: 'exec'; command: string; baseDir: string }
    | { op: 'read' | 'write' | 'delete'; path: string; baseDir: string }
    | { op: 'move'; path: string; destination: string; baseDir: string }
    | { op: 'search'; root: string; pattern?: string; baseDir: string } // без pattern — весь root
    | {
          op: 'mcp';
          server: string;
          tool: string;
          effect: 'read' | 'write' | 'unknown';
          derived: ToolOperation[];
      }
    | { op: 'fetch'; url: string }
    | { op: 'agent'; parentSession: string }
    | { op: 'inert'; what: string } // известное действие без защищаемого эффекта (план, todo)
    | { op: 'unknown'; why: string };

type ToolEvent = { operations: [ToolOperation, ...ToolOperation[]] }; // пустой вызов невалиден

type SessionContext = {
    sessionId: string;
    loop: boolean; // только по контракту запуска
    coreRevision: string;
    roots: { consumer: string; execution: string };
    policy: unknown; // доверенные данные контура: защищаемые пути, MCP с эффектами, таблица скиллов
    evidence: { skillDelivered(name: string, sha256: string): boolean };
};
```

Пути барьер судит по правилам разрешения, а не по строке: симлинк на защищённый файл,
запись через симлинк родителя, перенос каталога с защищённым содержимым, ещё не созданное
назначение. Поиск судится по множеству файлов, которые он может прочесть (`search` без
шаблона по корню, где лежит `.env`, — чтение `.env`). У MCP-вызова адаптер выражает
связанные файловые и сетевые эффекты параметров операциями `derived`: разрешённый
инструмент загрузки с путём `.env` в аргументе — то же чтение секрета.

## Набор соответствия

Матрица проб **генерируется из описания**: каждый элемент `toolMap`, `argMap`,
`eventCoverage`, каждая `configSurface`, запрещённая переменная, источник MCP. Полноту
самого описания проверяет **независимая сверка**: инвентарь инструментов и режимов,
который отдаёт CLI (список инструментов модели, флаги возможностей), против описания;
расхождение — красный. Незнакомый инструмент проверяется через настоящий диспетчер CLI,
а не вызовом нормализатора: matcher может отсеять его раньше.

- **фикстуры** — сырые события, снятые живьём с этой версии CLI на каждый элемент матрицы;
  собранная фикстура помечена как собранная;
- **отрицательные пробы** — запись данных контура каждым файловым классом, включая патч,
  move и запись через симлинк; косвенная запись скриптом, где защищённого пути нет в
  аргументах (держит песочница); запись поверхности конфига; `.env` путём, шаблоном
  `*.env`, `**/.env`, поиском без фильтра, симлинком; MCP-мутация вне списка; разрешённый
  MCP-инструмент с запрещённой целью; подменённый MCP-сервер; переменная, снимающая барьер;
  отброшенная регистрация; падающий, отсутствующий и зависший хук; у Codex — ввод кода в
  запущенный процесс, не только в оболочку; правка теста без скилла; поддельное
  доказательство в той же сессии, чужая сессия, битая история, усечённая доставка;
- **положительные** — та же матрица с разрешёнными целями: эффект есть;
- **независимость** — пакет пятого харнесса подключается настоящим путём раннера: конфиг,
  preflight, проба, сессия на фиктивном CLI. Дифф `core/` и `.claude/hooks/` пуст,
  запрещённых зависимостей модулей нет. Окончательно универсальность подтверждает только
  реальный CLI, не участвовавший в проектировании.

Обновление CLI = повтор набора на новой версии (R13): пакет закреплён за версией,
незнакомая версия не стартует до прогона.

## Изменения поведения у Claude Code

Контракт ужесточает Claude Code намеренно, и это не регресс: незнакомый инструмент
блокируется (было — пропуск); эффект MCP задаёт политика, а не префикс `List`/`Get` имени;
поверхности конфига Claude (`.claude/settings*.json`, `.mcp.json`) — в защищаемых путях.
Claude Code проходит ту же матрицу, что и остальные. Сохраняются перечисленные в наборе
разрешённые сценарии, существующие запреты не ослабляются.

## Новый харнесс

1. Пакет `adapters/harnesses/<имя>/` по таблице выше.
2. Фикстуры, снятые живьём на стенде по матрице из описания; сверка инвентаря CLI.
3. Зелёный набор соответствия и contract suite исходов; песочница для этого харнесса.
4. Допуск в роль — canary профиля (Фаза 17).

Если для нового CLI понадобилась правка общего барьера, значит, нормализованное событие или
контекст чего-то не выражают, и правятся они, а не барьер под харнесс.
