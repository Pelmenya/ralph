# Харнесс как пакет адаптера: контракт, по которому подключается любой агентный CLI

**Дата**: 2026-10-27
**Статус**: Draft, основание для Фаз 16c–16f (`roadmap/plan.md`). Вторые мнения — Kimi K3.1 Pro
и Codex gpt-6-astra, два круга: по контракту (16 и 18 находок) и по карточкам фаз (20 и 19).

**Что уже есть и чего ещё нет.** Фаза 16b проводит в запуск все четыре харнесса: Codex —
регистрацией в argv, Kimi Code — домом CLI, который раннер собирает перед сессией, OpenCode —
плагином (статус «экспериментальный»). Живая отрицательная проба у Kimi Code и OpenCode
пройдена на `Bash` и чтении `.env`. Общие барьеры при этом принимают вход в форме Claude Code,
а конфиг Kimi Code и OpenCode сливается с конфигом человека. Всё, что ниже названо событием,
пакетом и набором соответствия, — цель Фаз 16c–16f, а не описание текущего кода. Сделано (#186):
guard регистрации раннера у Claude Code судит `ToolEvent` его нормализатора; Codex, Kimi Code и
OpenCode до своих нормализаторов (16d) идут совместимым входом 16b.

Канон вырос на Claude Code, и его барьеры говорят на языке Claude Code: имена
инструментов `Edit`/`Write`/`Bash`, поле `file_path`, транскрипт JSONL с вызовом `Skill`,
`settings.json`, `mcp__<server>__<tool>`. Разбор 27.10 (бинари codex-cli 0.163.0, Kimi
Code 2.3.2, OpenCode 1.19.4, их документация и история сессий стенда Фазы 11) показал, что
у трёх харнессов в разных сочетаниях барьеры молча пропускают одни запреты и навсегда
блокируют другие.

Цель — чтобы подключение харнесса не было переносом допущений Claude по одному. Харнесс
подключается **пакетом адаптера** вне `core/` и общих барьеров: описание (данные),
нормализатор события, регистратор барьера, сборщик конфига и чтение истории (код).
Произвольный CLI одними данными не подключить, и документ этого не обещает. Обещание
другое: для нового CLI не правятся ядро и общие барьеры.

## Что нашёл разбор

Серьёзность: **дыра** — запрет проходит молча; **ложный блок** — разрешённое блокируется
без выхода; **дрейф** — поведение меняется без нашего ведома. Пометка «по доке» — живой
фикстуры события ещё нет.

Три общих корня. **Барьер, не узнавший событие, разрешает его** (`guard-rules.cjs`, ветка
«незнакомый инструмент» → `ALLOWED`): одно это правило дало половину дыр таблицы.
**Харнесс исполняет конфиг из дерева, которое правит агент**, причём уже при старте —
защита путей от записи не помогает, слой мог лежать в дереве до сессии. **Механизм
перехвата сам может отказать**, и у трёх CLI из четырёх отказ означает пропуск.

MCP-allowlist по имени у Kimi Code работает, как у Claude, но не покрывает подмену сервера
через конфиг. Codex и OpenCode на стенде проверялись только на `Bash`: их файловые пути и
MCP отрицательной пробой не покрыты.

## Принципы

1. **Незнакомое — запрет.** Инструмент не из описания, поле, которое не разобралось,
   MCP-имя без отображения в описании, невалидная операция — блок с причиной. Если
   невалидна или запрещена хотя бы одна операция вызова, запрещён весь вызов; все операции
   судятся до первого эффекта. Возможность, которую барьер не умеет судить (`fetch` без
   политики сети), запрещена, пока не умеет. Субагент (`agent`) и отложенный ход (`defer`)
   в сессии петли запрещены совсем: раннер не видит ни их ходов, ни их обрыва (#225).
2. **Общие барьеры не знают харнессов.** `guard-rules.cjs`, `skill-barrier.cjs` и проверка
   данных контура принимают нормализованное событие и доверенный контекст сессии. Сырой
   вход CLI до них не доходит. Независимость проверяется зависимостями модулей и
   отсутствием ветвления по идентичности харнесса; поиск имён — вспомогательная проверка.
3. **Хук — барьер качества, граница доверия — песочница.** Хук не видит путь, собранный
   скриптом по частям, и не держит отказ собственного механизма у CLI, которые такой отказ
   пропускают. Поэтому гарантия «агент не меняет конфиг, пакет, политику и доказательства»
   держится песочницей, где эти пути процессу сессии недоступны на запись, у каждого
   харнесса. Без успешной проверки песочницы сессия петли не стартует ни на одном харнессе;
   режим без песочницы — только ручной эксперимент, не роль петли.
4. **Исполняемый конфиг дерева не исполняется.** Конфиг харнесса собирает раннер в каталоге
   состояния. Проектные исполняемые слои (хуки, плагины, инструменты, MCP-серверы)
   выключаются; где нельзя — preflight отвергает их наличие в дереве и в его предках. CLI,
   у которого нельзя ни того, ни другого, набор соответствия не проходит.
5. **Регистрацию подтверждает CLI, а не наш разбор.** Проба идёт той же командой, с тем же
   окружением и домом, что сессия. Предупреждение CLI об отброшенной секции — отказ старта.
   Обработанная ошибка правила — блок двойкой со стабильным кодом причины (`reasonCode`);
   отказ механизма перехвата — блок там, где механизм наш (плагин OpenCode), и объявленное
   ограничение там, где нет. Стартовая проба на дереве потребителя исполняет только хуки на
   синтетическом входе; живая проба настоящим CLI — только на стенде.
6. **Доказательство — доверенное и полное.** Загрузку скилла фиксирует коллектор раннера
   вне процесса сессии по событиям потока CLI или плагина: успешное событие той же сессии,
   имя и хеш скилла, полная доставка, порядок до правки. История и кэш, которые сессия может
   записать сама, служат только корреляции и доказательством не являются. Где активации нет (Codex читает `SKILL.md` оболочкой), критерий называется
   честно — «эквивалентная доставка инструкций».
7. **Правила доставляет раннер.** Контракт сессии приходит в промпт или флагом инструкций
   харнесса, а не фразой «прочитай файл». Какие файлы правил харнесс читает сам и с каким
   бюджетом — объявление описания; доставка проверяется вместе с остальными инструкциями.
8. **Опасные пробы — только на стенде, и проба доказывает правило.** Живая отрицательная
   проба идёт в изолированном стенде с фиктивным MCP и безопасными целями. Зелёная проба —
   это свидетельства своего вида пробы (правило барьера, регистрация, отключённый канал,
   preflight, песочница): для пробы правила — попытка вызова, событие у барьера, ожидаемый
   `reasonCode` и отсутствие эффекта; у отказа preflight события у барьера нет и быть не
   должно. Каждая отрицательная проба — в паре с разрешённой, у которой эффект есть. Любой
   код 2 любого хука пробу не засчитывает. Стенд изолирован средствами ОС: запись только в
   его каталог, сеть — loopback фиктивного MCP и провайдер модели.

## Пакет адаптера

Каталог `adapters/harnesses/<имя>/` с версионированным интерфейсом. Реестр вне `core/`
находит пакет и проверяет его описание по схеме; ядро выбирает пакет по конфигу через шов.
Общий хук пакет не импортирует: он зовёт исполняемую команду адаптера, которая читает сырой
вход хука из stdin и отдаёт `ToolEvent` JSON с версией протокола; сбой команды или
незнакомая версия — блок. Контекст сессии раннер передаёт через окружение команды хука или
наследуемый дескриптор, а не файлом, который сессия может переписать. Сделано окружением
(#184): `RALPH_SESSION_CONTEXT` в env сессии, разбор хуком — `.claude/hooks/session-context.cjs`;
`policy` и `evidence` в него ещё не входят (#185, 16e). Каждая регистрация guard в настройках
сессии проходит пробу preflight с этим контекстом. Выбор харнесса по
`switch` в ядре и список `GUARD_WIRED_HARNESSES` ушли за реестр (#180, #213): все четыре
харнесса — пакеты, и способ пробы регистрации (команда хука или плагин CLI) пакет объявляет
полем `plugin`, а не ядро ветвлением по имени.

| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| описание        | версия CLI; `toolMap` (имя → операция); `argMap` (пути, шаблоны, назначение); `allowedFields` (полный перечень полей входа и конверта); `eventCoverage` (каналы — перехват или       | генератор матрицы проб; сверка с инвентарём самого CLI       |

| регистратор     | регистрация барьера в формате CLI, обратное чтение того, что уйдёт в CLI; признак принятия регистрации самим CLI                                                                     | проба на собранной команде                                   |

Вход общих барьеров — дискриминированное объединение с обязательными полями и исполняемой
валидацией:

```ts
type ToolOperation =
    | { op: 'exec'; command: string; baseDir: string }
    | { op: 'read' | 'write' | 'delete'; path: string; baseDir: string }
    | { op: 'move'; path: string; destination: string; baseDir: string }
    | { op: 'search'; root: string; contentPattern?: string; pathGlob?: string; baseDir: string } // без pathGlob — все файлы root; без contentPattern — только имена
    | {
          op: 'mcp';
          server: string;
          tool: string;
          effect: 'read' | 'write' | 'unknown';
          derived: ToolOperation[];
      }
    | { op: 'fetch'; url: string } // адрес или текст запроса наружу: WebSearch — тоже fetch
    | { op: 'agent'; parentSession: string } // порождает субагента
    | { op: 'defer'; what: string } // откладывает ход: пробуждение, расписание
    | { op: 'inert'; what: string } // известное действие без защищаемого эффекта (план, todo)
    | { op: 'unknown'; why: string; kind?: 'tool' | 'field' }; // tool — вне toolMap, field — поле вне перечня или не той формы; без kind — field

type ToolEvent = { operations: [ToolOperation, ...ToolOperation[]] }; // пустой вызов невалиден

type SessionContext = {
    sessionId: string;
    loop: boolean; // только по контракту запуска
    coreRevision: string;
    roots: { consumer: string; execution: string };
    policy: unknown; // доверенные данные контура: защищаемые пути, MCP с эффектами, таблица скиллов
    evidence: { skillDelivered(name: string, sha256: string): boolean };
};
```

Пути барьер судит по правилам разрешения, а не по строке: симлинк на защищённый файл,
запись через симлинк родителя, перенос каталога с защищённым содержимым, ещё не созданное
назначение. Поиск судится по множеству файлов, которые он может прочесть: `pathGlob` — по
диалекту шаблонов, без `pathGlob` — весь корень (поиск по корню, где лежит `.env`, — чтение
`.env`); значение `contentPattern` на решение о секрете не влияет, а его отсутствие значит
поиск имён (`Glob`): имена секрета не несут, и судится только сам корень. Цена названа: поиск
содержимого без `pathGlob` обходит корень на каждом вызове (до 50 000 записей, без `.git` и
`node_modules` — это предел, а не «там пусто») и блокируется env-файлом и под `.gitignore`. Сделано guard на событии (#187,
`physicalPath` и `judgeFileOperation` в `.claude/hooks/guard-rules.cjs`): путь разрешается
посегментно от `baseDir`, `..` после симлинка ведёт к родителю цели, висячая ссылка судится
целью, несозданное назначение — от ближайшего существующего предка. Перенос судится с обеих
сторон: источник — сам и содержимым каталога, назначение — новым путём (в существующий каталог —
`назначение/имя`). Поиск обходит каталоги-симлинки и судит ссылку внутри корня по цели, в том
числе под шаблоном её имени. Перенос каталога данных оболочкой (`mv`, `rm`, `cp`, …) держит
забор по аргументам, на событии — ещё и по файловой системе; так же git вне разрешённых
подкоманд (`checkout <ref> -- .claude`, `restore --source=…`), `find` с удалением или
программой вне читающих хотя бы в одном из `-exec` (без точки старта — от `.`, как его
обходит GNU find) и `tar` с извлечением, а шаблон оболочки
(`mv .c?aude bak`) раскрывается, как его раскроет оболочка. У git pathspec с шаблоном или
ведущим `:` (после `--` и позиционным у любой подкоманды, кроме известных без pathspec —
`branch`, `tag`, `fetch`, `push`, `merge`, … — так что алиас и незнакомая подкоманда судятся),
`--pathspec-from-file`, глобальные `--icase-pathspecs`/`--glob-pathspecs` и присваивание `GIT_*`
в строке (`GIT_ICASE_PATHSPECS=1`, `GIT_WORK_TREE=…`; кроме автора, редактора, пейджера и
трассировки) считаются совпавшими с данными: git читает их шире шаблона оболочки; шаблон
`--list`, refspec и текст сообщения (`-m`/`-F` только у `commit`, `merge`, `tag`, `stash`,
`notes`, в том числе склейкой `-qm`; у `checkout`/`restore` `-m` — флаг) pathspec'ом не судятся. `cd`
внутри той же строки разбор не отслеживает, смену дерева без пути (`git checkout <ветка>`,
`reset --hard`) забор не судит. Совместимый вход файловой системы не видит, поэтому путь из
одних `.` и `..` у заменяющего вызова (`find -delete`, `tar -xf x.tar`,
`git checkout <ref> -- .`) считает предком данных: каталог вызова может быть корнем дерева. Живые пробы — на стенде (`docs/install-stand.md`). У MCP-вызова адаптер выражает
связанные файловые и сетевые эффекты параметров операциями `derived`: разрешённый
инструмент загрузки с путём `.env` в аргументе — то же чтение секрета. Эффект MCP-инструмента
(`read`/`write`) задаёт политика контура (`mcp.tools.<имя>.effect`, разбор —
`consumer-data.cjs`); прежние `writeAllowed` и префиксы `List`/`Get` переводит в эффекты
мигратор `mcp-effects.cjs` по инвентарю инструментов, сверяя каждое решение с прежним. До
политики сети любой `derived` `fetch` блокируется.

## Инвентарь MCP

Какие MCP-инструменты существуют, знает не описание пакета и не человек, а сами серверы
потребителя (`core/mcp-inventory.ts`, #215). Решение принято 28.10 по второму мнению двух
моделей; отвергнуты файл, который ведёт человек (устаревает и полноты не доказывает),
транскрипты (в них только использованное), снимок в ядре (внешний сервер версионируется
отдельно) и снимок со стенда (фиктивный MCP стенда о боевом сервере ничего не говорит).

- **Источник** — живой `tools/list` каждого сервера из `.mcp.json` дерева потребителя, с
  теми же `command`, `args`, `env` и подстановкой `${VAR}`, что у петли. Опрашивает доверенная
  сторона (launcher, раннер), не сессия и не CLI харнесса: источник один для всех четырёх.
  Процесс сервера идёт с cwd дерева, из которого прочитан `.mcp.json` (не дерева ветки фазы), и
  с окружением по белому списку (`PATH`, `HOME`, локаль, прокси) плюс `env` своей записи; ключи
  петли, ключ живой пробы и токены форжа не раскрываются и не передаются никогда.
  Постраничная выдача проходится до конца; страница — отдельный процесс сервера по stdio.
  Сервер с `url` (http/sse) и серверы пользовательского слоя CLI сборщик не видит: первое —
  отказ с именем сервера, второе — их инструменты guard блокирует как незнакомые.
- **Снимок** — `.claude/ralph/mcp-inventory.json`, файл потребителя под ship. Поля:
  `schemaVersion` (сейчас 1), `collectedAt`, общий `hash`, `servers.<имя>` с `version`
  (`serverInfo.version`, не сообщил — `null`), своим `hash` и `tools[]` — канонические имена
  `mcp__<server>__<tool>`, имя у сервера и `inputSchema`. Хеши — sha256 содержимого с ключами
  по порядку: правка руками мимо сборщика видна.
- **Проверка** — отказ, если хотя бы один настроенный сервер не ответил, ответ неполный (нет
  `tools`, инструмент без имени, курсор повторился или не кончается), есть дубль, имя не
  каноническое, хеш не сходится, состав серверов разошёлся с настроенным, снимок пуст или
  версия формата незнакома (её сверяют первой и без разбора остального). Ключ политики —
  канонический `mcp__<server>__<tool>`; имена, которые харнесс выдаёт хуку иначе, переводит
  `mcpNames` его пакета. Пустой `mcpNames` — харнесс зовёт каноническими именами; непустой
  обязан покрыть каждое имя снимка ровно одним выданным именем: имя без перевода, перевод в
  инструмент вне снимка и два имени, переведённые в одно, — отказ.
- **Дрейф** — перед сессией раннер сравнивает снимок дерева человека со свежим опросом (при
  тех же `.mcp.json` и снимке — не чаще раза в час, в `--dry-run` — никогда) и называет
  строкой `⚠` по серверу, что добавлено, удалено, переименовано (та же непустая схема входа под
  другим именем, ровно один кандидат с каждой стороны), у чего сменилась схема и сменилась ли
  версия сервера. Сверка ничего не разрешает: новый инструмент guard блокирует кодом
  `mcp-not-allowed`, и его причина при политике эффектов называет блок дрейфом конфигурации, а
  не транзиентом, — вызов не повторяют; блок по запрету ядра по слову при заявленном эффекте
  назван политикой, а не дрейфом. Нет снимка, он битый или сервер молчит — тоже строка `⚠`: снимок guard
  не читает, и стоп сессии ничего не защитил бы.
- **Порядок при дрейфе**: человек (или launcher при обновлении, #218) собирает свежий снимок,
  мигрирует данные контура по нему и отдаёт PR, где снимок и `hooks.json` меняются вместе;
  после ship новый инструмент получает эффект, и только тогда петля может его звать.
- **PR обновления** (`./ralph update`, `core/update-bundle.ts`, #218) — один коммит с lock,
  данными и снимком, собранными из одной базы. Инвентарь недоступен или пуст — стоп до пуша.
  Свежий снимок проходит ту же проверку, что снимок из файла, с переводами `mcpNames` всех
  пакетов. Данные прежней формы мигрируются; уже мигрированные сверяются со снимком: чтение вне
  его — стоп, новое имя — строка `⚠`. Решения до и после миграции сравнивает настоящий
  `decideEvent` на `инвентарь ∪ writeAllowed` трижды: мигратор, launcher до публикации и гейт PR
  потребителя (`./ralph verify-mcp` в `gate.checks` — база PR против головы, только git). Гейт
  обещает эквивалентность только PR миграции; при уже мигрированной базе он отказывает лишь на
  чтении вне снимка, а изменённые решения называет строкой `⚠` — их держит ship человека.
  `./ralph rollback` возвращает данные и снимок вместе с lock тем же коммитом.

## Набор соответствия

Матрица проб **генерируется из описания**: каждый элемент `toolMap`, `argMap`,
`eventCoverage`, каждая `configSurface`, запрещённая переменная, источник MCP. Полноту
самого описания проверяет **независимая сверка**: инвентарь инструментов и режимов,
который отдаёт CLI (список инструментов модели, флаги возможностей), против описания;
расхождение — красный. Незнакомый инструмент проверяется через настоящий диспетчер CLI,
а не вызовом нормализатора: matcher может отсеять его раньше.

- **фикстуры** — сырые события, снятые живьём с этой версии CLI на каждый элемент матрицы;
  собранная фикстура помечена как собранная;
- **отрицательные пробы** — запись данных контура каждым файловым классом, включая патч,
  move и запись через симлинк; косвенная запись скриптом, где защищённого пути нет в
  аргументах (держит песочница); запись поверхности конфига; `.env` путём, шаблоном
  `*.env`, `**/.env`, поиском без фильтра, симлинком; MCP-мутация вне списка; разрешённый
  MCP-инструмент с запрещённой целью; подменённый MCP-сервер; переменная, снимающая барьер;
  отброшенная регистрация; падающий, отсутствующий и зависший хук; у Codex — ввод кода в
  запущенный процесс, не только в оболочку; правка теста без скилла; поддельное
  доказательство в той же сессии, чужая сессия, битая история, усечённая доставка;
- **положительные** — та же матрица с разрешёнными целями: эффект есть;
- **независимость** — пакет пятого харнесса подключается настоящим путём раннера: конфиг,
  preflight, проба, сессия на фиктивном CLI. Дифф `core/` и `.claude/hooks/` пуст,
  запрещённых зависимостей модулей нет. Окончательно универсальность подтверждает только
  реальный CLI, не участвовавший в проектировании.

**Виды проб и их свидетельства** (`adapters/probe-kinds.ts`, #183). Судья знает три исхода:
`proven` — свидетельства полны и исход заявленный; `failed` — свидетельства полны, а барьер не
удержал; `unproven` — свидетельств не хватает или они неоднозначны. Поле, которого стенд не
наблюдал, — отсутствие свидетельства, а не «не было».

| Вид               | Отрицательная: обязательные свидетельства и исход                                           | Разрешённая                                         |
| ----------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| правило барьера   | попытка вызова настоящим CLI, событие у барьера, код 2, ожидаемый `reasonCode`, эффекта нет | попытка, событие, код 0, эффект есть                |
| регистрация       | попытка запуска с отброшенной регистрацией, CLI не стартовал, отказ назван                  | подтверждение регистрации самим CLI, старт, событие |
| отключённый канал | попытка вызова по каналу, события у барьера нет (наблюдали), эффекта нет, отказ CLI назван  | — (пара — разрешённая проба того же CLI)            |
| preflight         | попытка запуска с запрещённой конфигурацией, отказ до старта, события у барьера нет         | запуск на чистой конфигурации стартовал             |
| песочница         | попытка записи, которой хук не видит, записи нет, отказ ОС назван                           | запись в разрешённый путь прошла                    |

Эффект — того вида, что у операции: у чтения и поиска это **выдача содержимого**, у записи,
удаления и переноса — изменение файловой системы, у регистрации и preflight — старт сессии.
Наблюдение другого вида свидетельством не считается. Отрицательная проба засчитывается только
вместе с доказанной парной разрешённой (`judgeWithPair`). Стартовая проба на дереве
потребителя (`core/guard-probe.ts`) исполняет хуки на синтетическом входе, попытки у неё нет,
и судьёй она не доказывается по построению — это проверка хука, а не живая проба.

**Генератор матрицы** (`adapters/harnesses/probe-matrix.ts`) выводит пробы из описания: на
каждый инструмент `toolMap` — отрицательные своей операции и разрешённая, поля входа — из
`argMap` (нет нужной роли — проблема матрицы, а не поле по догадке), прочие обязательные поля
инструмента — из `probeInputs` описания (минимальный валидный вход: разрешённая `Skill` с пустым
входом не разбиралась); у поиска без роли `contentPattern` отрицательных нет — он отдаёт только
имена; незнакомое поле входа у
каждого инструмента с разобранным входом и незнакомое поле конверта; каждое имя `mcpNames`;
незнакомый инструмент; канал `eventCoverage` — регистрация (перехвачен) или отключённый канал;
каждая `configSurface` — запись файловым инструментом и preflight; каждая `forbiddenEnv` —
preflight; косвенная запись скриптом — песочница. Пара — разрешённая той же операции, а где её
нет (fetch барьер пока не судит, agent и defer в петле запрещены, у незнакомого инструмента
разрешённой нет по определению) — общая разрешённая того же CLI.

**Живую пробу исполняет раннер, а не сессия** (#219). Сессии петли ключа CLI не дают, и guard
не пускает её к env-файлу, поэтому критерий карточки «живая проба на стенде» она выполнить не
может — по тому же принципу, что коллектор доказательства скилла (принцип 6). Сессия просит
пробу намерением `live-probe` с парой `cli` + `case` из закрытого каталога
(`adapters/live-probe-cases.ts`, сценарии `provision/install-stand.sh`), раннер после сессии и до
закрытия карточки исполняет её (`core/live-probe.ts`) и кладёт итог `RESULT … PASS|FAIL|INCONCLUSIVE`
с хвостом журнала комментарием в карточку. Граница доверия ключа:

- ключ пробы — отдельный, переменную называет конфиг потребителя (`liveProbe.keyEnv`); совпадение
  значения с ключом петли — отказ; без ключа — отказ с именем переменной, а не пропуск;
- процесс стенда собирается с чистого окружения: ключи петли и токен форжа туда не едут, внутрь
  изоляции — только ключ под именем CLI, `IS_SANDBOX=1` (без него CLI под root отказывает
  `bypassPermissions`) и адрес прокси хоста (`liveProbe.upstreamProxyEnv`) для цепочки выхода;
- исполнитель стенда (`install-stand.sh`, `provision/stand/*.mts`) — из установки ядра, а
  проверяемое (хуки, пакеты харнессов) — из дерева работы через `STAND_SUBJECT_ROOT`; раскладки
  корней нет или ядро внутри дерева работы — отказ;
- выход — только к провайдеру модели (белый список прокси стенда), каталог стенда — короткий
  (`/tmp/rp-…`: путь сокета прокси упирается в предел `sun_path`);
- провайдер-посредник вместо умолчания CLI — только из локального конфига: `liveProbe.baseUrl`
  (`https://хост[:порт]`, без пути, запроса и кредов) добавляет к белому списку ровно свой хост,
  `keyAs: "auth-token"` отдаёт ключ CLI токеном Bearer, `model` — имя модели, которого ждёт
  посредник; маршрут называет `adapters/live-probe-cases.ts`, CLI без маршрута — отказ;
- значение ключа вычищается из комментария, лога и файла намерений, а его след в выводе стенда —
  FAIL пробы.

PASS — `close` той же карточки, пришедший с пробой, применяется; FAIL, INCONCLUSIVE и отказ —
карточка остаётся открытой с причиной в комментарии, петля не встаёт. Каталог пока знает только
Claude Code: у остальных CLI маршрут ключа пробы в стенд не проверен живьём, и проба для них —
отказ разбора, а не прогон без авторизации.

### Коды причины

Блок барьера — код выхода 2 и последней строкой stderr машинная строка
`ralph-reason-code: <код>` (`adapters/barrier-reason.ts`). Строка ровно одна; нет её, их
несколько или код вне перечня — «не доказано». Код неисправности пробу правила не доказывает
никогда: барьер fail-closed блокирует всё той же двойкой, когда сломан. Литералы хуков и
перечень сверяет `adapters/barrier-reason.test.ts`.

| Код                   | Класс         | Кто выпускает  | Что значит                                                             |
| --------------------- | ------------- | -------------- | ---------------------------------------------------------------------- |
| `secret-env`          | правило       | guard          | чтение или правка env-файла                                            |
| `destructive`         | правило       | guard          | рекурсивное удаление, сброс дерева, force-push                         |
| `mcp-not-allowed`     | правило       | guard          | MCP-инструмент вне контура проекта                                     |
| `contour-data`        | правило       | guard          | правка данных контура хуков из сессии петли                            |
| `git-exec-input`      | правило       | guard          | git с исполняющим входом из сессии петли                               |
| `no-verify`           | правило       | guard          | `git commit --no-verify`                                               |
| `manifest-shell`      | правило       | guard          | правка `package.json` из оболочки                                      |
| `raw-address`         | правило       | guard          | сетевой вызов на голый адрес                                           |
| `host-service`        | правило       | guard          | изменение службы хоста                                                 |
| `foreign-kill`        | правило       | guard          | `kill` чужого процесса                                                 |
| `loop-push`           | правило       | guard          | `git push` из сессии петли: ветку фазы пушит раннер                    |
| `loop-delegation`     | правило       | guard          | субагент или отложенный ход в сессии петли: раннер их не видит         |
| `skill-required`      | правило       | барьер скиллов | правка без вызова обязательного скилла                                 |
| `unknown-tool`        | правило       | guard          | инструмент вне `toolMap`                                               |
| `unknown-field`       | правило       | guard          | поле входа или конверта вне `allowedFields`                            |
| `config-surface`      | правило       | после #186     | запись поверхности конфига харнесса                                    |
| `capability-unjudged` | правило       | guard          | возможность, которую барьер не судит: `fetch`                          |
| `input-invalid`       | неисправность | guard          | вход хука пуст, не JSON или не объект                                  |
| `rules-unloaded`      | неисправность | guard          | правила или данные контура не загрузились                              |
| `core-revision`       | неисправность | guard          | хук не сверился с ревизией ядра                                        |
| `rule-fault`          | неисправность | guard          | правило бросило или вернуло вердикт не того вида, в том числе без кода |
| `session-context`     | неисправность | guard          | контекст сессии от раннера заявлен, но битый или без обоих корней      |
| `skill-barrier-fault` | неисправность | барьер скиллов | вход, ревизия, таблица скиллов или транскрипт не позволили судить      |
| `adapter-failed`      | неисправность | guard          | нормализатор пакета не дал событие по протоколу                        |

Обновление CLI = сертификация новой версии (R13): пакет закреплён за версией, незнакомая
версия не стартует в роли петли и запускается только на стенде; после зелёных матрицы и
сверки инвентаря версия и сырой инвентарь вносятся в пакет отдельной правкой. До стенда
Фазы 16f отказа старта нет: раннер перед каждой сессией сверяет фактическую версию с
`cliVersion` описания и называет расхождение строкой `⚠` (`cliVersionDrift`), один раз на
версию за прогон.

## Изменения поведения у Claude Code

Контракт ужесточает Claude Code намеренно, и это не регресс. Сделано guard на событии (#186),
списком в `core/guard-event-scenarios.test.ts` — у каждого пункта и вердикт прежнего входа,
пропуск:

- незнакомый инструмент блокируется (было — пропуск), поле вне перечня — тоже;
- matcher guard накрывает все инструменты: `Monitor` с командой оболочки и `Glob` судятся
  (были мимо перечня имён), шаблон пути поиска — по диалекту, а не строкой;
- `fetch` в сессии петли — `capability-unjudged`, `agent` и `defer` — `loop-delegation`
  (#225); в сессии человека остаются.
  `WebSearch` — тоже `fetch`: текст запроса уходит наружу тем же каналом, что адрес;
- эффект MCP задаёт политика (`mcp.tools`), а не префикс `List`/`Get` имени, — когда данные
  контура её заявили; данные прежней формы судятся прежним правилом до миграции доверенным
  launcher (`mcp-effects.cjs`).
