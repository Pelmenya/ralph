# Вехи и карточки

Прочитай фазы плана: $ARGUMENTS

Для каждой новой фазы заведи веху и карточки в репозитории канона на его площадке
(`origin` этого дерева).

**Инструмент — MCP площадки, если он подключён; иначе её CLI.** Поведение площадки сверяй
с её документацией и OpenAPI, а не с интуицией от GitHub: она там систематически врёт
(статусов шесть, связь PR с карточкой — своя, slug меток — свой).

## Порядок действий

1. Прочитай фазы плана.
2. Проверь существующие вехи и открытые карточки — идемпотентность: дубль вехи или карточки
   хуже, чем лишний вопрос. Ищи полным списком, а не префиксом названия: поиск по началу
   строки молча пропускает карточку с другим первым словом.
3. Веха на фазу: название `Ralph · Ф{N}: {название}`, где номер и название — из заголовка
   фазы в плане (`### Фаза {N}: {название} (S…)`), без этапа в скобках. Одна форма имени на
   все вехи: по ней ищется существующая веха, и другая форма завела бы дубль.
4. Карточка на задачу: title, body, веха, **ровно одна метка сложности и ровно одна метка
   зоны** (разделы ниже).
5. **Фаза — в локальный конфиг петли.** Петля идёт по списку `common.phases` в
   `.claude/ralph/ralph.config.json` (файл локальный, в репозиторий не коммитится):
   `{ "milestone": "<название вехи>", "branch": "feature/f<N>-<slug>" }` на своё место в
   порядке. Веха без строки в конфиге петлёй не берётся никогда.
6. **Процесс раннера читает конфиг только при старте.** Фаза, добавленная во время работы,
   подхватится только после рестарта. Рестарт — на границе: в окне гейта мерджа текущей фазы
   или после её стопа. Иначе процесс уйдёт в следующую фазу по старому списку.

## Статусы карточки (их шесть)

`open` → `inProgress` → `closed`; плюс `paused`, `declined`, `duplicate`. Дубль закрывается
статусом `duplicate` с комментарием-ссылкой на оригинал, а не `closed`.

В выводе CLI статус — объект (`{id, slug, name, status_type}`): сравнивай `status.slug`,
а не строку. Ожидатель, сравнивавший строку `closed`, молчал бы вечно.

## Метки

Slug меток — с дефисом (`complexity-low`): площадка вырезает двоеточие из slug, а фильтры
идут по slug.

**Сложность (ровно одна — кроме карточек `human`)** — по ней раннер выбирает модель:

| Метка               | Когда ставить                                                          |
| ------------------- | ---------------------------------------------------------------------- |
| `complexity:low`    | Механика: перенос, конфиг, текст — без решений                         |
| `complexity:medium` | Типовая правка по образцу: модуль с тестами, адаптер по готовому шву   |
| `complexity:high`   | Инженерные решения: граница доверия, протокол, барьер                  |
| `complexity:expert` | Критично для корректности: мердж, откат, разбор ответа площадки        |

Сомневаешься между двумя — бери более высокий уровень.

**У карточки `human` метки `complexity:*` нет.** Раннер отвергает такое сочетание
fail-closed («конфликт замысла»: кто исполнитель?), причём по ВСЕМ карточкам вехи, а не по
той, что собрался брать. Одна карточка с обеими метками останавливает всю фазу при исправном
коде.

**Зона (ровно одна):** `area:core`, `area:adapters`, `area:docs`, `area:devops` — по
каталогу, который правит карточка; правила каталогов — в их `CLAUDE.md`.

## Тело карточки

- **Симптом → Причина → Что сделать → Критерии готовности.** Критерии — поведение, а не
  «написать тест»; у барьера — тест «от противного».
- **Решения человека — в тело карточки, а не в комментарий.** Сессия петли получает тело
  карточки, а ветку обсуждения не видит: сессия, которой решение не вписали, сделает работу
  по отвергнутому варианту.
- **Зависимости — номерами** («зависит от #N», «закрыть до …»). Номер — только реальной
  карточки этой площадки: площадка связывает PR и карточку по любому `#N` в тексте.
- **Никаких проектных следов**: ни имени потребителя, ни пути машины, ни адреса хоста —
  карточки публичные.

## Правила

- Порядок карточек = порядок задач в плане: петля берёт их по номеру. Заводи в том порядке,
  в каком их надо делать.
- Не выдумывай задач, которых нет в плане.
- **Карточка обязана помещаться в одну сессию**, фаза — **не больше 5 карточек** (скилл
  `plan-phase`). Увидел в плане крупную — не заводи как есть, вернись к `plan-phase`.
- Закрывает карточку описание PR строкой, НАЧИНАЮЩЕЙСЯ со слова «Закрывает» (корень канона,
  раздел Git), а не связь PR с карточкой.
- В конце — компактная сводка: веха → карточки по номерам → строка в конфиге.
