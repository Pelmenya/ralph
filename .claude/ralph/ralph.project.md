# Проектная половина промпт-контракта — канон как потребитель самого себя

> Этот файл — единственный `ralph.project.md`, который живёт в каноне. Остальные
> потребители держат свой у себя, и в канон он не попадает (`.gitignore`). Исключение
> законно ровно потому, что проект здесь — сам канон: файл описывает этот репозиторий,
> а не чужой, и следа потребителя в нём нет. Скан следов проверяет его наравне с кодом.
>
> Ядро сессии исполняет НЕ из этого дерева: раннер запущен из отдельной установки
> канона на зафиксированной ревизии. Правка ядра в ветке фазы вступает в силу только
> после мерджа и смены ревизии установки — то, что ты правишь, не то, что тебя ведёт.

## Стек и раскладка

- Язык и рантайм: TypeScript без билд-шага, нативный type stripping Node 24 — только
  erasable-синтаксис (ни `enum`, ни `namespace`, ни parameter properties).
- Зависимости: `npm ci`. Рантайм-зависимостей у ядра нет, только devDependencies гейта.
- Где что лежит: `core/` — оркестратор и правила петли, `adapters/` — швы форжа и
  рантаймов, `runtime/` — монитор, deadman, уведомления, `shared/` — общие детали,
  `tests/` — барьеры уровня репозитория, `.claude/hooks/` — guard и барьер скиллов
  сессий. Правила по папкам — в `CLAUDE.md` каждой из них; прочитай правила той
  папки, которую правишь.
- Точка входа: `ralph.js`.

## Команды проверок

Гейт мерджа — одна проверка `npm run gate` (`ralph.config.json` → `gate.checks`). Она
сама идёт fail-fast по шагам; отдельные шаги нужны, чтобы чинить быстрее:

| Проверка | Команда                | Что означает красный                                                                                                                |
| -------- | ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| формат   | `npm run format:check` | `npm run format`, руками не выравнивать                                                                                             |
| типы     | `npm run typecheck`    | чаще всего не-erasable синтаксис или тип коллаборатора разошёлся с реальной функцией                                                |
| сьют     | `npm test`             | сначала прочитай, какой барьер упал: `project-traces`, `core-purity`, `outside-deps`, `docs-coverage` — это барьеры, а не тесты фич |
| доки     | `npm run docs:check`   | правился `CLAUDE.md` без `npm run docs:sync`, либо `AGENTS.md` поправлен руками — правка источника, копию пересобирает генератор    |

Перед завершением сессии гони точечно затронутые наборы (`npx vitest run <файлы>`) и
`npm run typecheck`, `npm run format:check`. Весь сьют гоняет гейт раннера — второй
полный прогон в сессии только грузит машину.

## Большие файлы — только фрагментами

Целиком не читаются: `core/orchestrator.ts` (~13 тыс. строк), `core/orchestrator.test.ts`
(~19 тыс.), `core/session-settings.test.ts` и `core/gate.test.ts` (по ~2 тыс.). Порядок —
`rg -n '<символ>' core/orchestrator.ts`, затем чтение с `offset`/`limit` вокруг находки;
в тестах — `rg -n "describe\('<поведение>"`. Сессия, прочитавшая оркестратор целиком,
тратит контекст до первой правки (29.10.2026: семь минут чтения, ноль коммитов).
Новую логику клади в небольшой модуль рядом, а в оркестраторе оставляй только
подключение — так его не придётся читать и следующей сессии.

## Конвенции кода

- Зависимости функции приходят параметрами (`shFn`, `logFn`, `loadStateFn`, …), а не
  моком модуля. Нечего подменить в тесте — зависимость зашита не там.
- Пути — от `import.meta.dirname`, никогда от `process.cwd()`.
- Проектные ЗНАЧЕНИЯ — в конфиге потребителя, команды форжа — в `adapters/`. Ядро знает
  контракт, а не команды; сторожит `tests/core-purity.test.ts` с храповиком `DEBT`.
- Комментарий объясняет ПОЧЕМУ: докблок модуля называет инцидент и решение. Правишь
  код — правь и объяснение.
- Чего не делают никогда: не пишут имя проекта-потребителя, путь конкретной машины или
  адрес хоста — ни в коде, ни в комментарии, ни в сообщении коммита. Репозиторий
  публичный, историю `main` не переписать. Пример — только абстрактной формой
  (`/path/to/app`, `your-project`, `example.com`).
- Барьер не ослабляют, чтобы позеленеть. Правка файлов из списка `.sourcecraft/review.yaml`
  (гейт, предохранитель побочек, сканы следов и чистоты, хуки сессии) требует ship
  человека — такой PR петля сама не смерджит, и это задумано.

## Допустимые метки

Список закрытый: намерение с меткой не из него раннер отвергает целиком.

- `complexity:low` / `complexity:medium` / `complexity:high` / `complexity:expert` — оценка
  риска и инженерных решений в карточке (не её размера), ровно одна; по ней раннер
  выбирает модель.
- `area:core` — `core/`, `shared/`, `runtime/`, `ralph.js`.
- `area:adapters` — `adapters/`: швы форжа и рантаймов.
- `area:docs` — доки, `CLAUDE.md` и план.
- `area:devops` — CI, гейт, хуки, установка.

## Площадка и трекер

Сессия в трекер НЕ ходит — она пишет намерения (см. `ralph.md`).

- Форж: SourceCraft, репозиторий канона.
- Связь issue и PR: карточку закрывает строка описания PR, НАЧИНАЮЩАЯСЯ со слова
  «Закрывает» (`close-merged-issues.mts` после мерджа). Номер посреди фразы ничего не
  закрывает, но площадка привязывает PR к карточке по любому `#N` в тексте — в описании
  только номера, которые действительно закрываются.
- Доска: проекция статуса карточки, отдельной сущности нет.
- CI: облачный раннер площадки, свой прогон на PR. Красный чек площадки при зелёном
  локальном гейте — разница среды, а не флейк; подсказка — `forgeEnvHint` конфига.
