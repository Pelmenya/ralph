# `.claude/` — оснастка сессий в репозитории канона

Здесь лежит то, что получает сессия Claude Code, открытая в дереве канона: хуки, скиллы,
состояние между сессиями. Ядром это не является: потребитель держит свою `.claude/`, а
ядро приходит к нему каталогом или подмодулем. Общие правила репозитория — в
[корне канона](../CLAUDE.md).

| Путь                                                  | Что это                                                                                      |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `settings.json`                                       | проводка хуков: какой зовётся на каком событии и инструменте                                 |
| `hooks/guard.cjs`                                     | PreToolUse-барьер: секреты, деструктивное, MCP вне allowlist, службы хоста                   |
| `hooks/guard-rules.cjs`                               | правила барьера; `guard.cjs` только грузит их и держит fail-closed                           |
| `hooks/guard-shell.cjs`                               | политика над вызовами оболочки: удаление, сброс дерева, манифест, адреса                     |
| `hooks/shell-calls.cjs`                               | разбор команды оболочки в список вызовов (`sh -c`, подстановки, heredoc)                     |
| `hooks/guard-host-services.cjs`                       | systemctl, docker, Caddy — запрещено любое изменение состояния                               |
| `hooks/guard-process-kill.cjs`                        | `kill` — только свой процесс и только по литеральному pid                                    |
| `hooks/guard-wiring.ts`                               | сверка проводки: guard подключён и накрывает Bash, файловые инструменты, MCP                 |
| `hooks/skill-barrier.cjs`                             | правка теста в сессии петли — только после вызова `Skill(vitest)`                            |
| `hooks/core-revision.cjs`                             | контракт запуска `RALPH_CORE_SHA`: петля заявлена, хук сверен с ревизией ядра                |
| `hooks/consumer-data.cjs`                             | разбор данных потребителя для хуков: MCP-контур и таблица скиллов                            |
| `hooks/mcp-effects.cjs`                               | мигратор данных контура: явные эффекты MCP из `writeAllowed` и префикса                      |
| `hooks/session-context.cjs`                           | разбор доверенного контекста сессии от раннера (`RALPH_SESSION_CONTEXT`)                     |
| `hooks/adapter-event.cjs`                             | граница вызова нормализатора пакета: команда по протоколу, сбой — блок                       |
| `hooks/load-context.cjs`                              | SessionStart: подгружает `local/HANDOFF.md`                                                  |
| `hooks/sync-docs.cjs`                                 | PostToolUse: пересобирает `AGENTS.md` после правки `CLAUDE.md`                               |
| `skills/vitest/`                                      | скилл vitest (сгенерирован в antfu/skills), правится только регенерацией                     |
| `skills/prd/`, `skills/plan-phase/`, `skills/issues/` | цепочка планирования: раздел PRD → фазы ≤5–7 карточек → вехи, карточки, строка конфига петли |
| `skills/git-commit/`                                  | коммит по конвенции: сообщение проверяет `commit-msg.mts` до `git commit -F`                 |
| `local/HANDOFF.md`                                    | передача между сессиями; локальный, под `.gitignore`                                         |
| `ralph/ralph.project.md`                              | проектная половина промпта петли на каноне (конфиг рядом — локальный)                        |
| `ralph/hooks.json`                                    | данные канона как потребителя для хуков: MCP-мутации цикла, таблица скиллов                  |

## Местные правила

**Барьер держит только код выхода 2.** У PreToolUse код 1, таймаут и «не запустился»
Claude Code считает ошибкой без блокировки, и вызов исполняется. Поэтому любой отказ
самого барьера (не загрузились правила, правило бросило, вход не разобрался) обязан
кончаться двойкой, а не падением процесса. Под `bypassPermissions` `permissions.deny` не
действует вовсе, и упавший хук означал бы открытый канал.

**Блок называет причину кодом** (#183). Последняя строка stderr блока — `ralph-reason-code:
<код>` из перечня контракта (`docs/harness-contract.md`, «Коды причины»): правило — своим кодом,
отказ самого барьера — кодом неисправности (`rules-unloaded`, `rule-fault`, …). Проба засчитывает
двойку только с кодом своего правила, иначе сломанный барьер, блокирующий всё, проходил бы её.
Вердикт правил с `blocked: true` без кода — неисправность `rule-fault`. Новое правило — новый код
в перечне `adapters/barrier-reason.ts`; литералы хуков с ним сверяет тест.

**Работает ли барьер, проверяет раннер, а не тест.** Тест проводки сторожит ТЕКСТ
`settings.json`. Перед первой сессией раннер подаёт хукам заведомо запрещённые вызовы и
безобидный (`core/guard-probe.ts`) и не стартует, если запрещённое прошло или безобидное
не пропущено. Правишь хук — живой кейс `core/guard-probe.test.ts` прогоняет пробу на
настоящих хуках этой папки. Хуки этой папки — общие для всех харнессов (#119): Codex получает их
регистрацией в argv, Kimi Code — блоками `[[hooks]]`, OpenCode — плагином, который переводит его
событие в форму Claude Code; проба гоняет каждую регистрацию на событиях её CLI. Харнесс без
доказанной регистрации проба отвергает: сессия пошла бы мимо этой папки целиком. Барьер скиллов
в чужие регистрации не едет: он ищет вызов `Skill` в транскрипте Claude Code, а без транскрипта
в сессии петли блокирует, и правка тестов закрылась бы этим CLI навсегда. Старт говорит это
строкой `⚠` (`SKILL_BARRIER_LIMIT`). У Codex
«доказана» значит меньше, и старт говорит это строкой `⚠`. Оболочку и `apply_patch` guard судит
событием нормализатора пакета Codex (#232) — патч по каждому пути, — а проба старта подаёт патч
данных контура с контекстом петли. Ввод в процесс (`write_stdin`) хук не зовёт
вовсе (стенд #188), поэтому канал выключен флагом в регистрации барьера (`--disable
unified_exec_tty`, #190): без TTY stdin процесса закрыт, а argv без флага отвергает проба. Вызов
MCP у Codex guard судит событием политикой контура (проба старта — MCP-мутация, `mcp-not-allowed`),
а серверы MCP проекта держит не хук, а `--ignore-user-config` раннера: без доверия проекту
`.codex/config.toml` дерева Codex не грузит.

**Барьер минимальный, и это решение.** От потребителя переехало то, без чего петлю
нельзя пускать на канон ночью. Правила о номерах чужого трекера в тексте для площадки не
переехали: у канона «чужие» — потребители, а их имён в публичном дереве быть не может.
Перечня боевых служб хоста тоже нет — вместо «не трогай эти» здесь «не трогай ничего»
(почему — докблок `guard-host-services.cjs`).

**Исполняемое — ядра, контур — потребителя.** Код хуков едет с ядром, а то, что у проекта
своё, — MCP-мутации его форжа и таблица «файл → скилл», — лежит данными в
`<проект>/.claude/ralph/hooks.json`. Нет файла — самый строгий контур (ни одной
MCP-мутации, ни одного обязательного скилла); битый файл — блок, а не дефолт. Правка
данных меняет барьер так же, как правка кода, поэтому файл канона — под ship человека.

**Петлю заявляет раннер, а не текст промпта.** Сессия с `RALPH_CORE_SHA` — сессия петли,
и хук сверяет каждый свой `*.cjs` по содержимому с этой ревизией ядра: разошёлся файл,
лишний модуль, ревизия недоступна — блок любого вызова. Хук из дерева, которое правит PR,
— не тот барьер, который ревьюили. Сверка идёт ДО загрузки соседних модулей: `require`
исполняет код, и правленые правила, загруженные первыми, подменяли сверщик.

**Самосверка держит правку соседей, а не намеренный обход**, и это сказано вслух. Сверщик
(`core-revision.cjs`) и входной файл хука лежат в том же дереве и исполняются раньше
проверки: их правка снимает сверку в своём хуке. Два хука сверяют каталог независимо,
поэтому правленый вход одного ловит другой на общих инструментах. Барьер, которого правкой
дерева не снять, — регистрация хуков из установки ядра (Фаза 12). Установка обязана быть
git-репозиторием с объектом `RALPH_CORE_SHA` (клон, worktree или установка `./ralph install`
— она кладёт ревизию чекаутом в свой репозиторий): ожидаемые хеши берутся из `git ls-tree`, и
распакованный `git archive` под контрактом блокирует каждый вызов.

**Settings сессии петли собирает раннер** (`core/session-settings.ts`, задача 101). При
заданной раскладке корней перед каждой сессией он кладёт в каталог состояния файл и отдаёт
его флагом `--settings`: guard и барьер скиллов — абсолютным путём в каталог ядра, которое
исполняется, данные контура — из дерева человека переменной `RALPH_HOOKS_DATA` в команде
хука (`consumer-data.cjs` читает её раньше `CLAUDE_PROJECT_DIR`), остальное — настройки
дерева человека со всеми хуками потребителя, и `"disableAllHooks": false`. Затем проба на
собранном; не прошла — сессия не стартует. Проектные слои дерева сессии CLI не читает
вовсе (#194): источники настроек сняты (`--setting-sources ''`), MCP — строгий конфиг раннера,
`CLAUDE.md` и скиллы раннер отдаёт из дерева человека (скилл плагина зовётся `ralph:<папка>`,
барьер скиллов его засчитывает), а хук человека через `${CLAUDE_PROJECT_DIR}` исполняется
файлом дерева человека, а не ветки фазы. Без секции `roots` ядро — копия без своих хуков, и
сессии идут на настройках своего дерева, о чём старт говорит строкой в логе.

**Контракт `RALPH_CORE_SHA` раннер кладёт в команду своих хуков, а не в окружение сессии**
(#132). Значение — HEAD установки ядра; ядро не git-репозиторий или репозиторий чужой —
стоп на старте. Проба на собранном идёт с тем же контрактом: хук установки, разошедшийся с
ревизией, блокирует и безобидное, и раннер не стартует. Окружение сессии наследуют и хуки
дерева сессии, а у них контракт означал бы блок всего: на каноне — с первой правки хука в
ветке фазы, у потребителя — всегда (его каталог хуков не репозиторий ядра). Поэтому хуки
дерева сессии контракта не получают и петлю не узнают: барьер скиллов там — только по
`RALPH_SKILL_GUARD=on` (его раннер ставит в env сессии сам, если `roots` нет и своих хуков
он не регистрирует), строка `ralph.md` в промпте петлю больше не заявляет.

**Петлю guard дерева сессии узнаёт по доверенному контексту, а не по транскрипту** (#184).
Раннер кладёт `SessionContext` JSON в env каждой сессии петли (`RALPH_SESSION_CONTEXT`,
разбор — `session-context.cjs`), и хуки получают его наследованием: окружение процесса хука
порождает CLI, команды сессии его не переписывают, а файл она переписать могла бы. Корня два,
оба абсолютные: с `roots` потребитель — дерево человека, исполнение — дерево сессии; без
`roots` оба — дерево сессии. Из контекста guard берёт только `loop`: в сессии петли писать
данные контура файловым инструментом и вызовом оболочки нельзя (чтение и упоминание в тексте —
можно), и путь данных забор узнаёт шаблоном, а не относительно `roots.execution`. `roots`,
`coreRevision` и `sessionId` разбор сверяет по форме, но решений по ним guard пока не
принимает. Заявленный, но битый контекст — блок кодом `session-context`, а не «петли нет».
Прежний признак — строка `ralph.md` в промпте транскрипта — снят: сессия человека с похожим
промптом считалась петлёй, а у харнессов без транскрипта Claude признака не было.
Снятие держит проба preflight (`sessionContextProblems`): каждая регистрация `guard.cjs` в
настройках сессии получает правку данных контура с контекстом и обязана заблокировать её
своим кодом — регистрация, до которой контекст не дошёл, это отказ старта, а не `loop=false`.
Доказывает она это у хуков без контракта — хуков дерева и копии ядра без git. Канонический
хук установки несёт `RALPH_CORE_SHA` в команде, петлю узнаёт по нему и блок дал бы и без
контекста; контекст ему и не нужен.
Предел назван: Codex, Kimi Code и OpenCode получают контекст тем же env сессии, но что их CLI
отдаёт его хуку их регистрации, эта проба не проверяет — до пакетов 16d старт говорит это
строкой `⚠` у каждого такого маршрута (`CONTEXT_UNPROVEN_LIMIT`).

**Поверхности конфига харнессов в сессии петли не пишутся** (#199). Настройки, хуки, плагины и
MCP любого CLI решают, с каким барьером и серверами пойдёт следующая сессия, а правка в доме CLI
ещё и не видна ревью. Перечень — `protectedSurfaces` описаний пакетов, объединённый раннером в
контексте сессии; guard знает только его форму и блокирует запись, перенос и удаление кодом
`config-surface` на событии и на совместимом входе. Дом CLI судится раньше шаблонов дерева: его
история и кэш (исключения описания) лежат под каталогом, который снаружи был бы поверхностью.
Поле контекста в разборе хука необязательное, пока раннер установки его не присылает; без него
правило молчит. Предел — `cd` внутри строки оболочки и путь, собранный по частям.

**Субагент и отложенный ход в сессии петли запрещены двумя слоями** (#225). Сессия правок
раздала темы субагентам, один оборвался посреди хода, а родитель спал по `ScheduleWakeup` и
считал его работающим: пять коммитов не доехали, петля стояла час. Раннер не видит ни ходов, ни
обрыва субагента, а сессию `-p`, отложившую ход, снаружи не будит никто. Первый слой — флаг
запуска `--disallowedTools` (`buildClaudeArgs`), второй — guard: операции `agent` и `defer`
события и имена `Agent`, `Task`, `Workflow`, `ScheduleWakeup`, `CronCreate` совместимого входа
в сессии петли блокируются кодом `loop-delegation`, вне петли свободны. Класс инструмента
объявляет описание пакета (`toolMap`), и незнакомый инструмент того же класса — `unknown-tool`.
Что guard держит запрет, доказывает проба старта: `Agent` и `ScheduleWakeup` с контекстом
петли (`DELEGATION_PROBES` в `core/guard-probe.ts`) — хватает одной регистрации, назвавшей
правило, потому что CLI складывает хуки.

**Ряд барьера скиллов едет вместе со скиллом.** Правило, требующее скилл, которого нет в
`skills/`, заблокировало бы правку навсегда: вызвать его нечем. Тест сверяет это сам.

**Нормализатор пакета хук зовёт процессом, а не `require`** (`adapter-event.cjs`, #179).
Пакет харнесса (`adapters/harnesses/<имя>/`) подключается и меняется отдельно от этой папки, а
модуль, загруженный в процесс хука, исполнил бы непроверенный код раньше решения барьера.
Поэтому хук отдаёт сырой вход команде адаптера на stdin и принимает только
`{"protocol": N, "event": ToolEvent}`: не запустилась, упала, зависла, ответила не тем или
незнакомой версией — блок с причиной. Импорт пакета отсюда и из `core/` ловит
`tests/harness-package-deps.test.ts`.

**Guard судит событие, а не вход CLI** (#186). Регистрация раннера несёт в команде guard
абсолютный путь нормализатора пакета (`RALPH_GUARD_ADAPTER`, его даёт реестр через
`core/session-settings.ts`); хук отдаёт ему сырой вход и судит `ToolEvent` правилом
`decideEvent` (`guard-rules.cjs`). Незнакомое больше не разрешается: инструмент вне описания
пакета — `unknown-tool`, поле вне перечня — `unknown-field`, сбой нормализатора —
`adapter-failed`; `fetch` и `agent` в сессии петли — `capability-unjudged`. Matcher guard —
`.*`: инструмент, до которого хук не дошёл, барьер не видит вовсе (`Monitor` с командой
оболочки шёл мимо прежнего перечня имён). Путь пакета хук сам не собирает — это зависимость
барьера от пакетов, и `harness-package-deps` её ловит.

Совместимый вход 16b — прежний `decide` по имени инструмента — остаётся переходным, и он
назван: `RALPH_GUARD_INPUT=compat-16b` у пакета, объявившего его полем `guardInput` (сейчас — ни
у одного: Codex с #232, Kimi Code с #191 и OpenCode с #192 судят событием своего пакета), и
регистрация без пути нормализатора — настройки дерева
(`.claude/settings.json` здесь, копии хуков у потребителя). В сессии петли строгость держит
регистрация раннера: хуки дерева Claude Code складывает с ней, и пропустить за неё они не
могут. Барьер скиллов до своей карточки в 16e (#207) получает сырой вход отдельной
регистрацией, как раньше. Сценарии петли на событии, намеренные ужесточения у Claude Code
списком и промежуточное состояние четырёх регистраций — `core/guard-event-scenarios.test.ts`.

**Хуки — CommonJS без зависимостей.** Они запускаются до `npm ci` и в любом окружении;
типы для тестов — рядом, в `*.d.cts`. Тесты хуков проходят typecheck канона:
`tsconfig.json` включает `.claude/hooks/*.ts` явно, потому что `**` скрытые каталоги
пропускает.
